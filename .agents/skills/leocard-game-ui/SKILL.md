# LeoCard 游戏 UI

让新游戏和界面调整融入现有 LeoCard，优先使用已有组件与交互。配合 [coding-conventions](../coding-conventions/SKILL.md) 执行；新增游戏或玩法模式时，同时遵循 [leocard-new-game](../leocard-new-game/SKILL.md) 的完整接入流程。本技能不扩大用户指定的改动范围。

## 先选参考，再实现

- 检查未提交改动，保留并行工作。选一个玩法和信息密度接近的现有游戏，阅读其大厅、牌桌、交互及结算，不只照截图重做外观。
- 查阅 [公共组件入口](references/components.md) 中与任务有关的部分，确认当前接口及调用方。路径和函数以当前仓库为准。
- 游戏专属数据和规则留在游戏模块，公共外观、布局和反馈交给表现层。出现重复实现时，在合适层级补齐共用组件，不把具体游戏规则塞进通用 UI。
- 公共组件提供默认布局，允许游戏通过尺寸、内容和配置扩展；不强求所有牌桌完全一致，也不为单个差异复制整套界面。

## 风格与素材

- 普通牌桌沿用现有字体、配色、纹理按钮和 CozyUI 面板；Minecraft 竞猜沿用其 OreUI 皮肤。匹配同类界面的层级、留白和动效节奏，不混用两套风格。
- 优先使用 `UiAssets` 中的纹理、图标及正常、悬停、禁用状态。已有纹理能表达的面板和按钮，不用临时手绘圆角矩形替代。新增图标匹配同类素材的材质、轮廓和视觉大小；既有 SVG 系列继续使用 SVG，用户要求生图时再采用生图。
- 保持纹理边框厚度和凹凸层次。按素材选择整图缩放或九宫格切片，核对源像素边距与角缩放；不能将面板边框压成细线，也不能让内容底色覆盖内框。像素素材的采样沿用现有加载设置。
- 使用公共 `TEXT`、`MUTED`、`ACCENT`、`READY`、`DANGER` 等语义色。弱化文字仍需可读；禁用控件保留位置，采用公共禁用样式。

## 优先复用的界面

- **准备大厅**：沿用 `LobbyPage` 的左侧规则、右侧座位骨架。标题右侧可放模式下拉框，下方可放简短说明及配置行；UNO 和 Minecraft 竞猜均有案例。复用配置控件、房主权限与禁用态，不各写一套模式选择。
- **玩家框与座位**：复用头像、玩家资料与互动菜单、房主和准备标记、剩余牌数等能力。人数分布先查公共 `seats`，再按游戏调整。核对最少和最多人数；人数未超过旧布局上限时保留合适的原布局。
- **结算**：优先使用公共排名结算、滚分、准备头像和结算动作。区分小局与整场，显示局内分数及权威结果给出的档案分数增减，不在 UI 重新计算奖励。结算仍可进行玩家互动。面板须容纳全部玩家，必要时分栏或滚动，不能用四人高度硬装六至八人。
- **按钮与弹窗**：牌桌按钮使用 `GameButtonSpec` / `add_textured_game_button`，公共页面使用对应的 CozyUI/OreUI 控件。确认操作复用二择弹窗及动画，提示复用现有消息组件。不可交互的信息栏、标题和拖动把手不套普通按钮的按压弹动。
- **输入和滚动**：使用现有文本编辑器、候选词与纹理滚动条，沿用焦点、IME、键盘和触摸行为。候选在回合或焦点变化后也要更新，不只监听文字。滚动范围按实际内容计算，轨道与滑块的悬停行为遵循现有控件。

## 手牌与动画

- 扑克牌优先复用 `CardSize`、手牌布局、`CardDragSelection`、拖选预览及 `HandCardHighlight`，保留悬停展开、选中抬升、呼吸高亮和取消选择的语义。不同牌种保留必要差异，不复制相同动画公式。
- 牌面尺寸、重叠间距、槽位宽度与命中区域保持一致。长手牌靠近头像时，点击应落在实际可见的牌上；装饰层和飞行动画避免拦截输入。结算、托管及旁观状态沿用当前操作权限。
- 分数变化复用公共滚动与加分反馈，页面切换沿用公共转场。使用现有缓动，避免跳位；动画坐标与静态布局使用同一坐标系和几何来源。
- 沿用 `UiComposer` 和当前场景组合方式，优先局部更新变化的文本、样式和状态。需要重建时保留焦点、编辑、滚动、拖动位置与动画进度，避免闪烁、重复候选或事件重播。
- 一次性反馈由对局标识、事件序列或现有播放状态驱动，不因重复快照或 UI 重建重新播放。跨区域运动放到适当的公共效果层，检查祖先裁剪，避免在面板边缘截断。

## Android 必要适配

- 同时检查桌面和 Android 分支。共用按钮及侧边控件优先复用 `GAME_SIDE_CONTROL_SCALE`（当前 Android 为 1.5、桌面为 1.0）；先查组件是否已缩放，避免父子重复放大。牌面可沿用游戏自己的现有比例，不给全窗口再乘一次倍率。
- 放大时同步调整文字、图标、容器、手牌重叠间距和操作区高度，以及飞牌起终点、选中偏移、弹窗锚点和实际命中区域。只放大绘制结果不算完成适配。
- 手机横屏按窄长比例考虑（含接近 21:9）：优先减少无效上下留白并分配可用宽度，保证手牌、桌面出牌、玩家框和操作按钮可见；沿用安全边距与折叠顶栏空间。
- 抽屉等贴边元素锚定实际界面边缘，处理设计画布缩放后的偏移，不靠单个窗口的固定补偿修补缝隙。浮窗限制在可见区域，内容多时向有空间的方向展开或滚动。
- 核对触摸点击、拖动、取消和软键盘遮挡。悬停、右键才能完成的必要操作应有触摸入口；可复用已有等价入口，不为范围外界面重写整套输入。
- 麻将等已有专门移动端布局的游戏，遵循其分支（如隐藏牌山、扩大牌桌与手牌），不直接套桌面坐标。新增素材也进入现有 Android 打包链路。

## 验收与交付

- 核对改动涉及的小窗口、最大化、手机横屏与人数上下限；重点检查换行、纹理边框、溢出裁剪、遮挡和可点击区域。涉及滚动或重建时，检查状态保持与动画去重。
- 按影响范围执行 rustfmt、Clippy 和必要的既有测试；有 Android 分支时尽可能检查 Android 目标。普通外观和位置调整不新增机械 UI 测试，核心交互变化才补针对性测试。
- 不默认启动游戏试玩，遵循用户安排。有截图或渲染结果时自行检查；未真机验证或未启动界面时明确说明，不能把编译通过称为视觉验收通过。
